# 大型落地镗铣床数字化加工单元
## Three.js 三维交互演示场景设计 V1.0

**版本：** V1.0（场景与交互设计基线）  
**编制日期：** 2026-10-15  
**用途：** 客户技术交流、建设方案讲解、研发演示工程实施依据  
**状态：** 待客户机床型号、工件几何和现场布局核实后进入真实设备建模  
**依据：**《单台大型落地镗铣床数字化加工与在线检测系统建设方案 V1.0》（2026-10-12）

> **核心定位：** 用一个连贯的三维工业场景，解释“研发工艺设计—离线受控交接—DNC/MDC 现场执行—大型轴孔加工—在机测量—独立终检与质量追溯”。首版属于**可交互的建设方案演示**，不宣称具备真实 CNC 运动控制、可放行的机床级碰撞仿真或正式同轴度计量能力。

# 1. 背景、目标与范围

## 1.1 建设背景

前期构想包含多机自动化产线、机器人上下料、自动物流和 MOM 调度。经客户沟通，本期严格收敛为：**1 台大型落地镗铣床 + 1 间机旁独立工作间 + 研发端 CAM/机床仿真 + 关键孔系在线检测**。生产安全域与互联网、研发办公网物理隔离，不存在跨域在线传输，不能在工作间远程启动机床。

关键产品为某大型装备，当前应展示两类加工对象：①侧面安装孔系；②左右车轮轴孔及其大跨距轴线关系。客户尚未交付经确认的完整 STEP/PMI、同轴度数值、机床准确型号、工艺装夹方案，因此首期模型必须带“示意模型 / 模拟数据”标识。

## 1.2 演示目标与评价问题

| 要解释的问题 | 必须给观众看到的证据 | 对应场景 |
|---|---|---|
| 为什么需要建设？ | 大型工件、双侧轴孔、装夹/基准、作业复杂度 | 01、04 |
| 研发软件起什么作用？ | 孔特征、装夹、刀路、机床运动检查、NC/检测程序审批 | 02 |
| 为什么要离线传输？ | 物理隔离、人工介质、安全检查、版本校验 | 03 |
| 工作间解决什么问题？ | 受控下发、设备采集、报警、执行履历 | 03、05 |
| 加工和测量如何衔接？ | 粗精镗、测头进孔、多截面采点、轴线拟合、人工复核 | 04、05 |
| 项目最后留下什么？ | 程序、设备、测量和质量报告的关联追溯 | 06 |

## 1.3 本期包含与不包含

**包含：** 全车间三维鸟瞰、镗铣床结构与示意运动、夹具与工件、侧面孔/两侧轴孔工艺展示、虚拟研发工艺工作区、受控介质人工传递、机旁独立工作间、DNC/MDC 面板、在线测量点/截面/轴线、质量追溯、自动讲解/自由交互、离线静态部署。

**不包含：** 多台机床组成的自动产线、机器人上下料、跨网远程管理、现场 CNC 控制、真实材料去除仿真、可替代终检的计量判定、未经实机数据验证的机床碰撞放行、生产级 MES/MOM。

# 2. 场景空间与视觉布局

## 2.1 一个主渲染世界，两个业务层次

**真实生产空间：** 单一 Three.js `Scene` 内包含车间壳体、地坪、线轨、落地镗铣床、工件、工作台、夹具、CNC 操作站、机旁独立工作间和受控介质接收点。摄像机持续穿行，不通过频繁换页破坏空间感。

**研发流程空间：** 研发侧**不应画在机床同一个联网车间里**。进入第 2 幕时，镜头聚焦悬浮式“数字工艺展示台”或独立数字舞台，以图形层解释 CAD/CAM/机床仿真；第 3 幕通过人工交接动画回到真实生产空间。此为叙事层，不等于研发室和车间物理相邻。

## 2.3 美术规范

- **整体观感：** 明亮、真实的工业厂房，钢结构/地坪/柔和冷白光；工业设备金属灰，安全警示用黄，UI 信息采用低饱和青蓝，不使用炫目的科幻霓虹。
- **镜头层级：** 鸟瞰 30% / 中景作业 35% / 主轴、孔、测头与数据特写 35%（拍摄分配建议）。
- **信息层：** 三维标牌定位工位；技术说明通过 DOM 叠加面板，不将大量小字体贴到 3D 几何材质上；前景保留完整可视空间。
- **真实度：** 厂房、工件、机床在整体比例上可信；关键加工部位精细，远景建筑简化；避免从错位的 3D 元件造成假工艺逻辑。
- **状态颜色：** 待机灰、运行青、报警琥珀/红、检测蓝、已核验绿。必须同时显示文字状态，不能仅靠颜色传达。

# 3. 六幕叙事与镜头脚本

建议自动导览总时长 **约 4–6 分钟（演示节奏建议，非项目要求）**；每幕可自由跳转，暂停后可进入探索模式。镜头路径和动画使用可配置脚本，支持未来调整配音或字幕节奏。

| 幕次 | 建议时长 | 镜头与主画面 | 动画与数据浮层 | 核心说明 |
|---|---:|---|---|---|
| 01 全景与痛点 | 35–45 秒 | 厂房顶视→大工件→落地镗铣床→双侧轴孔放大 | 车间区域依次高亮、左右孔轴线预览 | 一台设备怎样加工大型、高精度的多组孔系 |
| 02 研发端工艺 | 45–65 秒 | 切入隔离的数字工艺舞台，工件透明高亮 | CAD/PMI→孔特征→加工工序→刀路→机床仿真→NC 签发 | 程序上机前怎样验证、审批与冻结 |
| 03 物理隔离与下发 | 35–50 秒 | 工艺发布包特写→人员携带介质→工作间→机床控制站 | SHA-256、签名审批、导入检查、DNC 受控下发；显示断开的研发网络 | 网络不连通但业务链仍可追溯 |
| 04 现场加工 | 70–100 秒 | 工件定位特写→立柱、主轴箱、镗轴运动→两侧孔 | 机床轴向箭头、装夹基准、粗精加工、执行状态 | 如何控制运动、刀具和两侧轴孔加工风险 |
| 05 MDC 与在线检测 | 50–75 秒 | 工作间屏幕→机床测头→孔内多截面点集→两条拟合轴线 | 主轴/进给/报警、采点/截面拟合/角度与偏移示意、异常复核 | 过程监测、在线测量和人工处置如何协同 |
| 06 报告与价值 | 30–45 秒 | 机床、工作间与工件组合镜头→电子履历 | NC 版本、加工时间、测量记录、独立终检、追溯关联 | 留下可信的数据闭环，而不是孤立的软件大屏 |

**第 04 幕的分支：** 不能默认“左右轴孔一次装夹完成”。在有现场机床与工件数据之前，镜头旁显示“单次装夹可达性待核验”，**演示推荐使用经说明的二装夹/转位示例或抽象两侧孔对齐示意**。未来核实可达后，才能解锁“一次装夹加工”分支。

**第 05 幕的判断：** 在机测量只输出过程评估；公差边界附近显示“需复核”，不可渲染为正式合格。终检由客户认可的独立计量手段执行。

# 4. 机床端作业与加工动画规则

## 4.1 机床对象树与运动轴

建议使用可配置的 kinematic chain；下面仅是**示意**的常见落地镗铣床结构，不是现场型号认定：

```
FactoryRoot
└─ MachineRoot（机床安装坐标系）
   ├─ Bed / Rail（基础、地轨、导轨罩）
   ├─ XCarriage（沿床身导轨移动）
   │  └─ Column（立柱）
   │     └─ YHeadstock（主轴箱升降）
   │        └─ ZRam（滑枕伸缩，按实机定义）
   │           └─ WSpindle（镗轴进给，仅当实机具备）
   │              └─ ToolAssembly（主轴接口→刀柄→镗杆→刀尖）
   ├─ CNCPendant（机床现场控制站）
   └─ WorkZone（固定或独立工作台、夹具与工件）
```

- Three.js 场景统一 **Y-up、右手系**，单元米；机械/工件输入通常为毫米，导入时显式执行 `mm → m` 转换，不对 CAD 数据做任意镜像。
- 实机机床轴名、正向、行程、零点、回转附件、主轴接口、刀柄装配长度必须通过独立机床配置文件描述；默认示意轴并不代表正式运动学。
- `MachineFrame`、`WorkpieceFrame`、`SetupFrame`、`ToolFrame`、`TipFrame` 的坐标变换分别保存，不得将屏幕世界坐标当机床坐标；刀尖的位置来源于装配变换而不是视觉几何中心。
- 各独立机械部件拆分 GLB 层级节点，以节点矩阵/关节参数驱动动画。场景动画只模拟过程；未来真实 NC 轨迹接入需另行验证映射。
- 轨道尽头软限位、主轴与工件间距离、机床罩壳和立柱碰撞只做**提示性警示**；没有实机几何与验证算法时不能对外标记“仿真 PASS”。

## 4.2 工件与夹具

**首版示意工件：** 大型焊接或箱体装备结构，表面有成组侧孔、左右大直径车轮轴孔，并有明显基准面。其形状与真实客户工件无等价关系，标题明确“典型工件示意”。

**夹具：** 支撑块、定位挡块、压板、辅助支点以简化几何表现。换装夹方案可以展示 ①第一装夹找正与左侧加工 ②人员确认后转位/重新装夹 ③重新校准坐标 ④另一侧加工；转位动作须标注“工艺示意”，不得显示自动化翻转设备作为已建设内容。

## 4.3 八个连续作业动作

1. **工件落位**：吊装预留区与大型工件定位；吊装动作可选，默认不画自动化起重闭环。
2. **装夹与找正**：定位支撑、压紧与基准点闪烁，`G54` 仅在与真实工艺相符时使用，不固定写死。
3. **刀具装配**：刀柄—镗杆—刀尖依次分解组合，弹出刀具及补偿版本。
4. **快速定位**：立柱、主轴箱、滑枕做不同速度的轴向运动；运动源为一条授权演示路径。
5. **侧面安装孔加工**：孔群排序、定位、粗镗/精镗阶段切换；只做局部切削意图/刀路轨迹，不画真实材料去除。
6. **左/右轴孔加工**：高亮两孔空间轴线与定位基准，展示一侧孔加工与另一侧装夹处理的流程分支。
7. **测头测量**：主轴换装测头，触发点依次出现；显示采样、拟合、偏差可视化。
8. **异常与人工处置**：出现“需要复测 / 余量评估”的分支，不自动改刀补、不在工作间远程启动或复位 CNC。

**动画可复现性：** 播放速率可设 0.5×/1×/2×，可定位工序时间点，暂停时机床与 UI 同步冻结，重播可恢复相同初始状态；不允许不同组件各自使用与统一时间轴无关的循环动画。

# 5. 工作间、工业软件与安全流程

## 5.1 工作间的可视构成

工业 PC/显示屏、独立程序接收节点、DNC/MDC 应用画面、专用工业交换机、UPS、离线备份装置、门禁与线缆防护。屏幕内容不在三维物体上呈现密集文本；摄像机靠近时展开专门的 HTML 数据面板。

## 5.2 DNC/MDC 的职责界限

| 子系统 | 三维上要演示的动作 | 明确禁用/澄清 |
|---|---|---|
| 研发 CAM | CAD 特征与刀路生成、机床级工艺检查、NC/测量程序输出、审批 | 不宣称已具备生产级加工精度 |
| 受控交接 | 介质编号、审批、签名、完整性校验、安全检查 | 不绘制研发网到工作间的数字链路 |
| DNC | 程序校验、入库、版本选取、指定 CNC、受控传输 | 下发 ≠ 自动循环启动 |
| MDC | 当前状态、时间、轴位、主轴、程序、报警；历史查询 | 默认只读；字段缺失标“接口不可得” |
| CNC | 现场安全确认后，由操作员启动加工 | 不由网页/工作间遥控运动、急停或复位 |
| 在线检测 | 测头触测、孔截面与轴线拟合、过程评估 | 不等同于独立最终质量判定 |
| 质量追溯 | 工件、装夹、程序、轴孔测量、独立终检关联 | 演示数据标明“模拟” |

## 5.3 监控看板建议

顶部显示：`机床 ID`、`任务号`、`当前 NC 版本`、`当前状态`；中部为轴位置/主轴转速/进给倍率/运行时间（如接口可得）；下部为报警、程序下发记录、测量任务、处置备注；历史页支持按工件号、程序版本和日期检索。**演示模式禁止出现像真实现场实测一样的随机伪实时数据**，采用预先声明的模拟时序，右上角持续显示“模拟数据”。

# 6. 在机测量与双侧轴孔可视化设计

## 6.1 视觉对象

- 每侧轴孔各展示至少两个轴向分离的截面；各截面显示**多个圆周触测点**与最小二乘示意拟合圆。
- 拟合圆中心沿轴向关联，表现空间轴线 `AxisLeft` 与 `AxisRight`；三维中显示两轴的相对位置和角度。
- 量测页面展示 `测量基准`、`截面编号`、`测头状态`、`拟合结果`、`测量不确定度/复核要求`。示意可输出“轴线偏移、夹角”，但不把它们直接冒充正式图纸同轴度公差判定。
- 同一工件下关联首件、粗加工后和精加工后的过程测量。靠近边界的异常示例显示“转入独立复测”，不自动写入 CNC 刀具补偿。

## 6.2 数据与呈现限制

- 采点模拟需使用固定记录集和明确单位，禁止随机漂移导致同一演示不同结果。
- 正式质量评价需要客户图纸指定的基准体系、几何公差定义、仪器能力与不确定度；Three.js 只负责**结果呈现**，不是计量标准执行引擎。
- 终检场景将“在线过程测量”和“独立终检报告”呈现为两个不同记录来源与审核状态。

# 7. 交互与界面详细设计

## 7.1 页面构图

- **中心：** 约 75–85% 宽幅三维主视窗，默认为连续车间世界。
- **顶栏：** 项目名称、六幕选择、自动导览/自由探索切换、全屏入口、声音开关。
- **左侧可折叠信息区：** 当前场景叙事标题、关键技术说明、可选工序步骤；默认紧凑，不大面积遮盖三维。
- **底部时间轴：** 上一幕/下一幕、播放暂停、拖动定位、速度、进度。
- **右侧上下文面板：** 用户点击机床、工件、孔、测头或工作间时才出现设备详情与工艺/测量数据。
- **选中反馈：** 轮廓发光、局部透明/剖切、关联件高亮；同屏只显示一个主要交互上下文，避免多个面板遮挡。

## 7.2 自由探索热点

| 热点对象 | 点击后内容 |
|---|---|
| 机床立柱/主轴箱/镗轴 | 部件名称、运动方向、行程（未知则不显示数值）、运行示意 |
| 工件 | 工件/装夹基准、两类孔与示意工艺顺序 |
| 左/右轴孔 | 目标轴线、加工阶段、测量截面与点集 |
| 刀具与测头 | 主轴接口—刀柄—镗杆—刀尖装配示意、测量动作 |
| CNC 操作站 | 现场循环启动与联锁责任边界 |
| 工作间 | 介质接收、DNC 程序库、MDC 状态与质量记录 |
| 安全边界 | 研发/生产不可联网与人工介质交接 |

## 7.3 无障碍与稳定操作

鼠标左键旋转、滚轮缩放、右键平移；点击某幕后镜头平滑飞行并允许返回；`Esc` 关闭浮层/退出热点；支持键盘上一幕/下一幕、播放暂停。相机避开地坪穿模与不可达角度；任何场景跳转都应恢复合理视角。演示时持续显示标题/关键说明/“模拟”标识。

# 8. Three.js 技术实施架构

## 8.1 前端架构建议

- TypeScript + Vite + Three.js（版本锁定在实施时经过验收的稳定版本）。
- **一个 Renderer、一个主 Scene、一个 Camera 管理器**，采用场景图分层和脚本导览，不为每幕重复创建 WebGL 上下文。
- WebGL 作为首期兼容性基线；WebGPU 渲染作为后续可选能力，需在目标离线浏览器和 GPU 上专项验证。
- 3D 模型优先 `.glb`（glTF 2.0），`GLTFLoader` 统一加载；几何与贴图单独优化，视实际模型用 Meshopt/Draco、KTX2，需随离线包附上解码依赖。
- 机床运动分离 `MachineKinematics` 和 `DemoTimeline`：前者输入关节参数产生层级变换，后者只负责时间轴和场景状态，避免硬编码动画污染机械模型。
- `AnimationMixer` 适合厂房物件/简化机构的预制动作；对机床轴关节优先采取由统一时间轴驱动的显式变换，以保证暂停、拖动与复播一致。
- 选中检测使用 `Raycaster` / 语义热点，成批小部件采用几何共享/实例化；使用模型层级 LOD 与可见性裁剪控制负载。
- UI 采用 DOM/CSS 叠加；数据通过明确的 JSON 事件模型驱动，不写在 shader 或 3D mesh 文本中。

## 8.2 逻辑模块

```
src/
  app/              # 演示入口、全屏与模式切换
  scene/            # 主 Scene、渲染器、环境、灯光、可见性
  assets/           # GLB 目录及 Manifest、单位/轴向转换
  machine/          # 运动学层级、坐标框架、工件与装夹
  director/         # 六幕脚本、镜头轨道、时间轴、跳转复位
  sequences/        # 作业/工艺/数据事件序列
  overlays/         # 场景热点、标签、流程 UI、DNC/MDC 面板
  measurement/      # 截面点、拟合圆/轴线显示（示意数据）
  data/             # 离线可复现模拟数据与 Schema
  security/         # 隔离边界和审批交接表现层
  tests/            # 时间轴、变换、交互及跨浏览器回归
public/
  models/           # 机床/工件/车间/工作间 GLB
  textures/         # 贴图/HDRI/字体

```

# 11. 质量指标与验收清单

**工程验收（V1 建议目标，须结合展示电脑性能冻结）：**

1. **离线运行：** 所有 JS、字体、模型、贴图和解码器都本地加载；断网状态下完整演示六幕；不调用 CDN/云服务。
2. **交互稳定：** 100 次幕间跳转、暂停/拖动/重播无状态串幕、工件或轴位置漂移、浮层遗留。
3. **坐标与运动：** 明确 Y-up、右手系、单位变换；所有刀尖、工件基准和孔轴线都通过父子矩阵转换校验，禁止直接把 World 坐标冒充 Machine 坐标。
4. **可信叙事：** 一台机床、一个工作间、研发与现场无网络连接；现场 CNC 启动由操作员负责；在机检测不代替终检。
5. **渲染体验：** 目标演示机在 1920×1080 分辨率下以稳定 30 FPS 为 P0，60 FPS 为优化目标；负载指标需在约定硬件、浏览器和完整资产包上实测，不预先承诺低配置均可达成。
6. **资源尺寸：** 制定加载预算、模型拆分和贴图压缩策略；首屏优先呈现主机轮廓，工作间与精细零部件延迟加载。
7. **内容准确性：** 示意模型、模拟数据、待核验精度标识可见；客户正式资料及第三方模型授权清晰。

**演示验收（最低功能点）：**

- [ ] 六幕自动演示完整可播、暂停、跳转、重新播放。
- [ ] 一台大型镗铣床与工件的空间关系清晰。
- [ ] 可以选中立柱、主轴箱、滑枕、刀具、工件、左右轴孔、测头与工作间。
- [ ] 机床示意动作符合其层级和配置，不将所有部件平移当作真实加工运动。
- [ ] 研发端与生产端物理隔离；DNC 与 MDC 职责明确。
- [ ] 两侧轴孔多截面测量和轴线拟合可视化。
- [ ] 异常分支展示人工复核、独立终检和追溯报告。
- [ ] “示意”与“模拟数据”有持续醒目标注。
