## 3. 核心验收脚本

1. 运行 `npm install && npm run dev`，确认屏幕能看到工业厂房、镗铣床和战车车体，无黑色完整遮挡物、渲染崩溃或资源 404。
2. 在工件装夹视角确认：顶部炮塔敞口实际镂空，侧面轮孔实际镂空，五组成对；不能用颜色贴片代替孔洞。
3. 阶段“机床找正”接近 30% 时，目标孔显示为 0.0 mm（**模拟计算结果**）；横移中不得显示 0.0 mm。
4. 在 39–57%、67–83% 分别检查 A/B 两孔的镗杆与孔中心线重合，并确认滑枕进退无穿透侧板的展示错误。
5. 在 30–39% 检查 DNC 局域传输光点。验证画面没有从研发站到机床网的直接网络线。
6. 在 83–93% 检查：钻镗刀具切换为蓝色虚拟测头，X/Y 对准选定轮孔，滑枕靠近但不碰穿轮孔；左右测点仅为计划状态。
7. 在 93–100% 检查：先退刀后横移，不能带伸出的虚拟测头横向通过工件。
8. 点击小面板“过程数据”，先见摘要；再展开完整 JSON；拖动时间轴后确认内容刷新。复制和下载的 `simulated` 应始终为 `true`、`quality.measured` 应为 `false`。
9. 在 1920×1080 和 1366×768 检查右侧单栏信息：不相互覆盖，展开小数据面板不会导致画面无法操作。
10. `npm test` 应全部通过，`npm run build` 应成功。

## 4. 不应宣称的功能

- CAM 页是研发流程与特征次序示意，不是完整 CAM 策略、真实刀位或可执行 NC。
- 测头仅为虚拟工具装配、点位规划和姿态演示，没有真实标定/触发/测点、不确定度评定及测量补偿。
- 选择的一组成对轮轴孔沿车体宽度方向规划共轴；场景未证明该机床可以加工另一侧，也未验证是否需要翻转装夹。
- 为解释检测思路而设置的薄壁双截面，不足以证明大型工件真实空间同轴度；最终应采用经批准的独立测量方案。
- 所有面板数据与 JSON 记录都是模拟，不是 CNC 采集值。

## 5. M5 建议开发

优先级 P0：客户明确机床型号、数控系统、X/Y/Z/W 行程和实际轴方向；获取真实车体 STEP 与装夹、刀具、刀柄、镗杆和基准数据，固化单一 CAD / Machine 坐标链。

P1：补齐真正的多工序 CAM/NC 与机床级运动学及干涉检查，界面只展示已验证的轨迹，不用示意动画冒充安全放行。

P2：厂家认可的只读 MDC 与受控 DNC 适配、数据落库、介质交接审计；不存在远程启停。

P3：经计量部门批准的在机测量方案，测头标定、足量截面、空间轴拟合、不确定度分析及独立终检比对；测量结果不能未经人工审批自动回写 CNC。
